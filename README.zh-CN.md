# ghidart

[English](README.md) | 简体中文

Dart AOT 的 Ghidra 扩展，目前支持 ARM64。
复用 Ghidra 官方 ARM64 源码和反编译器，保留原始指令和寄存器存储。

提供：

- Dart managed ABI：X15 栈、CPU/FPU/栈参数、返回值和寄存器保存规则。
- 独立的机器码函数发现、控制流分析和调用链参数/返回值恢复。
- 依据支持的机器码模式恢复 RuntimeEntry、写屏障、栈检查及 Mint helper 契约。
- 使用标准符号扩展运算，更清晰地表达压缩 Smi 提取。
- 可选根据机器码中的内存使用推导参数访问布局，不依赖快照布局。
- 索引 PP 相对访问和常量用途，为已证明的具体地址和调用建立引用。
- 复用原生 switch／SSA 分析，经过完整 CFG 校验后恢复有限间接跳转。
- 可选原生堆基址表达式命名及明确长度的字符数据类型。
- 可选解析 AOT 快照，恢复函数入口、明确长度的字符串和按池区分的对象池数据（L2）。
- 可选 b4a 集成（L3）：从统一 `b4a.json` 导入边界、分层类/函数名、原始字段布局、
  Thread/池描述、操作数引用和仅在 Listing 中显示的 IL。

**仍是实验项目，正确性与稳定性尚未经过全面验证。** 未知间接跳转、SDK 或调用约定保留为未知。
通用 native/FFI、动态栈上的活跃 Runtime 返回值和实机调试尚未完整支持或验收。
b4a 打印的类型和 IL 作为导出证据显示，不直接转换为物理 ABI 或替换 P-code。

## 安装

预编译 ZIP 可从 [Releases](https://github.com/yzctzl/ghidart/releases) 下载，
请使用发布说明指定的 Ghidra 版本。推送 tag 时自动使用最新稳定版 Ghidra 构建；
手动运行工作流可指定 Ghidra 发布 tag。构建成功仅代表编译与打包通过，不代表完整运行验收。

需要 Ghidra 12.2 PUBLIC、Java 25；项目自带 Gradle Wrapper。

```sh
export JAVA_HOME=/path/to/jdk-25
export GHIDRA_INSTALL_DIR=/path/to/ghidra_12.2_PUBLIC
./gradlew --no-daemon buildExtension
```

在 Ghidra 的 **File → Install Extensions** 中安装 `dist/` 下的 ZIP，然后重启。
也可执行 `./gradlew --no-daemon installExtension`，安装到上述 Ghidra 目录。
更新已打开的 Ghidra 时仍需重启。

## 使用

1. ELF 导入选择 **Dart AOT ELF**。Mach-O 使用官方加载器，选择语言
   `AARCH64:LE:64:dart`、编译器 `dart`（若是 2.13 时代独立 x23 堆基址的二进制，则选择 `dart-r23`）；FAT 文件选择 ARM64 slice。
2. Dart 分析器默认关闭，存在配套 JSON 时也不会自动执行。
   从 **Analysis → One Shot** 选择一种函数边界来源：
   - 快照格式受支持、没有 b4a 数据：手动执行 **Dart AOT Objects**（L2），创建函数、
     入口标签、字符串、对象关系和按池区分的数据。
   - 有匹配的 `b4a.json`：手动执行 **Dart b4a Import**（L3）。
     执行时自动查找二进制旁的配套 JSON，也可在分析选项中指定 **b4a.json path**。
     L3 优先提供边界和名称；再运行 L2 解析对象、字符串和池引用，不重复创建 L3 的边界或覆盖其名称。
     L3 失败时，边界也由 L2 提供。
     **Dart ABI** 保持独立；**Dart AOT Code Boundaries** 对所有快照格式均默认关闭，
     需要只导入边界时从 One Shot 手动运行。它不发布 THR/PP 视图；
     这部分请手动运行 **Dart AOT Objects**，不要求导入 b4a。
   - 快照不可读或经过自定义修改：选中 managed 可执行区域，执行
     **Dart Machine Code Functions**（L1）；必要时通过 **Confirmed entry addresses** 补充入口。
3. 选中关注的函数，执行 **Dart Value Uses**，然后打开反编译窗口。
   它默认先恢复物理 ABI，再将已证明的对象类型和池值接入伪代码；
   只需要 ABI 恢复时，单独执行 **Dart ABI**。
   仅在需要保留现有自动契约时关闭 **Recover ABI before value analysis**。
   L2／b4a 提供函数边界本身不等于恢复物理 ABI。

选择 **Dart → Show Analysis Status**，查看已保存的各层记录、最近一次 L2 尝试、
当前物理原型及此函数是否运行过值分析。记录数量不代表正确率或覆盖率。
语言升级后请保存数据库，避免下次打开时重复升级。

Dart 语言下，这六项均可通过 **Analysis → One Shot** 执行。
L2 和 b4a 导入始终读取完整输入，不受选区限制；选区用于限定机器码发现范围
和 ABI／值分析的起始函数集合。L2 无法解析新输入时，可在独立确认边界的指令图像内
自动执行 L1 函数发现；没有可靠边界时，需要手动选择托管代码范围。
拒绝解析时保留已有 L2 数据；b4a 导入和 ABI 分析仍需显式执行。
语言 **upgrade** 只更新数据库的语言模型，
不会重新分析，也不会修改数据库中保存的分析选项。

机器码发现和 ABI 分析默认关闭，避免扫描混合的 native 代码或在导入时全量反编译。
不完整控制流标记为 `Dart: incomplete CFG`；用户修改的范围、签名和调用点原型会被保护。
ghidart 的消息显示在 Ghidra Console 中。Dart 语言使用 `VMSP`、`THR` 等寄存器名；
物理名 `x15`、`x26` 等仍是同一寄存器的别名，供调试使用。

L1 ABI 分析依据机器码，不依赖快照 hash 或 Thread 布局配置。
**Dart ABI → Infer observed memory shapes** 可进一步把参数相对地址访问显示为偏移成员。
该选项默认关闭，需要已恢复的物理原型；混合数值运算或逃逸的参数不会推导。
这些类型只描述实际观察到的访问，不是 Dart 类或完整对象。重分析会撤销未修改的自动类型；
编辑过的布局会作为用户原型保留。

对选中函数运行 **Dart Value Uses**。默认先恢复物理 ABI，再按选中函数的调用依赖处理，
先被调用方、后调用方。未选中的被调用方保留已有契约，需要时一并选中。它逐个反编译函数，全库运行
可能耗时较长。任务进度显示当前函数、阶段和完成数量；单函数反编译超时默认 20 秒，
可在选项中调整，结束汇总包含失败和超时数量。该分析将 PP 来源、字节偏移、访问宽度
和常量用途保存到数据库。通过 **Dart → Show Value Uses** 可在 Console 查询。
具体地址引用使用 Ghidra 原生导航；PP 偏移本身不代表池条目或字符串。
修改代码或签名后需要重新分析。该分析默认关闭。

**Dart Value Uses → Name heap-base expressions** 可将精确的 `HBS << 32`
中间值命名为 `heap_base`，保留可见的真实运算，不改变指令、寄存器或调用契约。
重分析会删除未修改的自动名称，保留用户修改。该选项默认关闭。

独立确定字符数据的地址、字节长度与编码后，可通过 Data Type Manager 对该范围应用
内置类型 `dart_chars8`（Latin-1）或 `dart_chars16le`（UTF-16LE）。数据库和 Listing
保留 NUL 及 UTF-16 码元；原始 UTF-16 码元通过 Bytes 编辑。这些类型不发现 Dart
对象，也不猜测长度或编码。原生反编译器内联字符指针时仍遵循 C 字符串规则，
不能完整内联包含中间 NUL 的内容。
在已定义的字符数据或引用它的指令上选择 **Dart → Show Characters**，可在控制台查看
完整内容、地址、字节长度和转义码元。该视图保留 NUL 和孤立代理码元，不改变反编译语义。
对支持的快照，可在 **Dart ABI** 前执行 **Dart AOT Objects**。
这个 L2 分析器独立读取映射中的快照符号，不依赖 b4a；创建函数边界及多入口标签，
将字符串原始字符区定义到 **Defined Strings**，将对象身份和池槽保存为数据库记录。
通过 **Symbol Tree → Namespaces → Packages / SDK / App / Runtime / Unresolved** 查看声明。
包 URI 保留“包 → 路径 → 类”的层级；混淆后无法恢复 URI 的库归入 **Packages → UnknownSource**，不猜包名。
**Unresolved → isolate / vm / 加载单元作用域** 则存放尚未归到保留声明的代码。
这里是快照作用域，不是库名；代码仍可进行边界和 ABI 分析，不猜缺失的归属和名字。
**Dart → Analysis Status** 和 **Browse Dart Records** 会解释当前函数的分类；
匹配的 b4a 数据可以补充名字和所属关系。
顶层函数属于库，方法及已知分配/字段 stub 属于类。共享代码保留单一函数体和各作用域的声明别名。
编译器提供的符号保留在原地址，保留的 Dart 声明以别名补充。
尚未分析的 Loader miss／其他入口占位体可转为标签，真实方法从 normal 入口创建函数；
已经分析过的函数保持原样。
Dart 2.10–2.18 的旧数据库若在 ARM64 +20 入口修正前已发布 L2，需重新导入；
ghidart 会明确提示，不会静默沿用错误边界。
Ghidra 的 Functions 树主要显示全局函数；按归属浏览使用 Namespaces，搜索全部物理函数使用 **Window → Functions**。

在代码或字符串处选择 **Dart → Browse Dart Records**，通过停靠面板查看对象和池关系。
双击关系可继续查看；真实位置同时跳转 Listing，**Back** 返回上一条记录。
字符串位置直接显示正文、字节长度和编码；**Raw records** 查看完整保存数据。
关系按每页 200 条显示，**Filter page** 过滤当前页；悬停单元格查看完整名称或地址。
共享对象保留全部关系，无需一次性向界面填充数十万行。
逻辑身份显示作用域、记录编号和名称，不冒充堆地址，也不再生成符号树标签或普通 XREF。
代码到字符串的引用仍指向原始字符区，可从 **Defined Strings → References** 返回真实使用处。
仅元数据使用的字符串通过记录面板访问。池关系表示快照初始值，不保证运行时修改后不变。
字符串的序列化前缀与正文分别定义。
**Dart → Explain Pool Value** 在加载指令或 PP 槽位处解释能否替换为原生字符串字面量，
与反编译器共用证据检查。可变槽位、来源不唯一或字符无法无损表示时保留原始加载。
记录面板的 **Class Layout** 可直接在 Ghidra Data Types 树中定位已解码的类结构。
有匹配的 b4a 类布局时，L2 匿名槽位会在同一个原生 Structure 中补上字段名。
两种导入顺序均支持；尺寸、存储和用户修改过的成员保持不变。

经验证的 L2/L3 payload 会合并未经修改的 L1 函数拆分；用户或导入的名称、原型、局部变量，
以及手改函数体均受保护。范围改变会撤销旧的值使用事实，之后对这些函数重新运行
**Dart Value Uses**。


**Library → THR** 列出实际观察到的 Thread 偏移，有 b4a 时补充字段名；**Library → PP → scope → pool** 列出解析出的池槽。
只有 b4a 时暂归 **PP → Export**，L2 确定全局池后复用同一视图。
选择字段或槽位，可通过普通 **XREF** 返回真实使用指令；目标显示为 `THR:偏移`、`PP:偏移`
或区分池的具名 PP 地址，不再指向裸 `OTHER` 记录。这些是非加载的偏移模型，字节保持未知，
不是运行时内存或常量对象指针。对象之间的关系仍在 Dart Records 中，不进入普通 XREF。
未使用的字段不会伪造引用。THR 偏移引用直接来自已解码指令，不依赖布局；
字段名需要匹配的 b4a 导出，L2 独立提供对象池身份。**PP** 是指向 **ObjectPool**
（有时简称 OP）的寄存器，不是另一组对象。槽位的值列展示已解码的**初始值**或字符串；
THR 展示字段／偏移，无法静态获取的内容标为 `runtime value`。
这些导航模型不是内存转储，因此原始字节列仍保持未知。
真实加载／写入指令旁的 **Dart Analysis** 字段展示对应槽位或字段说明。
其他入口的标签归入所属函数，不再在每条 XREF 中重复列出入口角色。
这些逻辑身份不是运行时堆地址。声明关系、类型、逻辑签名和
已解码的整数保存在数据库属性中；逻辑参数数量不会替代机器码 ABI 推断。
同时保留序列化对象字段与字节区间。已适配的根表布局还将命名根引用、字段值／偏移引用和静态字段表
保存为可导航的槽位。静态字段（包括共享字段）链接到快照中的初始值，
不代表运行后修改的值；Type 和实例链接到所属类。Code 对象和已解析的 dispatch 条目链接到指令入口；
延迟加载目标在对应加载单元可用前保持未解析。即使没有本地函数体，也保留 Function 声明到 Code 的关系；
`LazyCompile` 标为辅助入口，不误标为已编译业务函数。逻辑对象和池槽显示整数及 Double 值，
Double 同时保留精确位模式。
固定大小的用户类布局位于 **Data Type Manager → Dart → L2**。字段位置从目标字单位
转换成字节偏移；tagged 槽位不冒充 native 指针，未知的 unboxed 数字类型保留为原始存储。
继承字段沿已保留的父类关系命名。SDK 定义的 null、布尔值和 sentinel 等基础对象
及内部 Class 对象在对象图中保留命名记录。
VM 缓存对象保留独立身份，不猜测文件中没有的运行时内容。

打开延迟单元 `*-<id>.part.so`／`.dylib` 时，将根文件及祖先单元放在旁边。
L2 临时读取父引用表，验证程序身份后应用该单元的 Code／池补丁；其他文件名可通过
**Parent AOT file** 指定直接父二进制。缺少父文件或身份不符时拒绝 L2，不编造地址。
ABI 恢复后，**Dart Value Uses** 可为明确对应的池／THR 加载局部变量命名。
未知的字值使用无符号物理字类型，不猜测对象类型；保留用户修改。
名称可带出已知的初始字符串／基础对象提示，不将可变的快照初始值折叠为常量。
这些名字绑定到原生 C 局部变量，保留真实的内存读取。无法对整个合并变量建立证据的值和没有符号的临时表达式保持内联。`Name THR values` 控制 Thread 加载命名；有 b4a 时使用字段名，
否则使用已观察到的偏移。
还会沿 SSA 搬移和无歧义合并追踪类分配结果、不可 patch 的池实例；明确的字段访问
链接到保留的 Field 声明，包括继承字段，生成的局部变量带出类名／字段名。
稳定池实例及所有分支均能证明属于同一 Class 的合并局部变量，也参与类型传播；
实例不同不代表类型不同，任一分支未知或可 patch 时，不为整个变量赋予该类型。
整个 SSA 局部变量能证明持有同一 Class 的完整 tagged 指针时，使用 Ghidra 原生的
偏移指针类型显示 `ADJ(obj)->field`；压缩值仍保留为整数。
receiver 匹配将 x4 与位置参数分开计数，支持可选参数方法中已证明的 x1 receiver。
其他输入可以只使用 32 位，receiver 仍必须是完整的 64 位 tagged 指针；
动态变化的可选参数栈位置保持未知。
已证明的入口 receiver 和返回类型写入原生原型，不改变参数数量或物理存储；
入口 receiver 关系可在 Dart Records 中浏览，Value Uses 会报告写入的原生类型数量。
调用方因此能沿返回类型访问字段。重分析在恢复 ABI 前撤销未被用户修改的生成类型，
避免旧局部变量把已经失效的结论重新推导回来；用户原型保持不变。
已验证的 SDK 分配根角色可恢复 x0 返回值，纠正原生存活性分析丢失或误判为多字返回的情况。
解码出的共享 Mint／栈检查角色复用 L1 的 helper 模型；没有 L2 时仍独立走机器码路径。
栈暂存及合流后的返回值还由原生 SSA 核对，只证明结果寄存器和宽度，
不证明未知调用前后对象身份不变；仅有 x0 存活并不能证明它是返回值。

稳定的字符串池加载接入 Ghidra 原生常量池，Unicode 等字面量直接出现在伪代码表达式中。
它们的类型是管理引用 `DartStringRef`，不是指向文件字符区的指针。可 patch 槽位、
歧义引用、缺少 L2 证据时保留原始 LOAD。内嵌 NUL、孤立 UTF-16 单元也保留在
显式长度数据和原始加载中，避免原生 C 字面量打印截断或替换内容。机器字节、Listing 和调试寄存器不变，
解释器中的标记保持恒等语义。已有数据库需正常升级到语言版本 1.2。

**Dart → Show Value Uses** 可查看对象、实参和返回值的来源。
未知调用、歧义值或缺失声明会停止传播，不将逻辑签名替换为物理 ABI。
hash 只提供候选读取器：匹配失败后回退到完整结构解码，互相矛盾的解读会被拒绝。
完整版本覆盖仍在实现中。仅凭池偏移仍不能确定代码访问点对应哪个对象或字符串。

L2 需要手动执行；导入二进制不会自动触发整幅 Dart 代码的反汇编。未知格式、未适配的根表或非法 cluster 数据会被拒绝，L1 保持独立。
成功执行时，控制台会报告函数名、字符串、池槽位数量及 `Root stream fully consumed`；
`L2 rejected` 表示没有发布任何 L2 数据。
相同输入可以重复执行；已发布快照的字节或映射发生变化时，会保留旧数据并拒绝替换，
二进制变化或旧版已发布数据的代次不兼容时，应重新导入项目。格式配置仅覆盖选定的 SDK 布局，
不代表 2.10 至 3.13 的每个版本都已经支持。

为支持的栈检查和写屏障调用点建立局部契约；直接 shared helper 还需要验证保存、恢复和结果槽。
无法确定目标地址的间接调用保留原样。L2/L3 元数据可提供更强的信息。

## b4a 集成（L3）

对配套的 ARM64 ELF 或 Mach-O 执行 **Analysis → One Shot → Dart b4a Import**。
执行时自动查找二进制旁的配套 JSON，不会在导入二进制时启动。
已保存的分析选项优先于新的默认值。
原始文件身份和加载后的 RVA 校验必须一致。
导入使用事务，取消或失败时回滚；相同文档重复执行会跳过。不同文档需要新数据库，
避免静默替换已有用户修改。
大导出文件可能需要数分钟及磁盘临时空间；较小的内存 `/tmp` 可能耗尽。
需要时在启动 Ghidra 前设置 Java 参数 `-Djava.io.tmpdir=/path/on/disk`。

通过 **Symbol Tree → Namespaces → Packages / SDK / App → 路径 → 类** 查看方法和别名，
通过 **Data Type Manager → Dart → B4a → Classes** 查看原始类布局。
不再建立重复的 `Entries` 树；缺少类声明的导出函数归入 **Runtime**，用户修改受到保护。

IL 和操作数描述显示在 Listing 的 **Dart Analysis** 字段，不再写入反编译器读取的普通注释。
**DartViewsPlugin** 在打开 Dart 程序时自动加入此字段；需要时在 **File → Configure** 中启用插件。
完整记录可通过 **Dart → Show Dart Records** 查看。JSON 头部、Code 范围记录和空 padding
不再生成可见的数据槽位。

L2/L3 共用库和类的层级。L3 优先提供名称、声明和边界；L2 提供对象、真实字符串字节和对象池身份。
L2 也补充导出缺少的备用入口和不重叠 helper，不替换已有函数体；类作用域与记录按 CID 关联。
导出的 Thread/池描述保留在 Listing；当 L2 证明的 PP 访问与导出偏移匹配时，描述附加到同一个按池区分的槽位。
不再创建 `B4aValues` 副本或指向描述地址的引用；代码到字符的引用仍指向原始文件中的真实字符串。

序列化 Class/Function/Code 身份和池关系保存在独立的双向索引中。
内部 `OTHER` 键只用于数据库身份；分析生成的对象关系不再进入普通 XREF 或命名空间树。
用户自己建立的引用和标签受到保护。原始类布局位于 Data Type Manager。
`objs.txt` 是实例文本 dump；JSON 提供类元数据，L2 提供对象图。
快照无法解析时，L3 的名称和注释仍可使用，但不会伪造缺失的对象地址。**Dart ABI** 仍需照常运行。

重新导入同一文档会升级旧的全零槽位和描述 overlay，保留用户代码名称和注释；
修改过的合成元数据会被拒绝迁移，避免丢失用户工作。随后运行 **Dart AOT Objects** 刷新 L2。
旧版生成的对象引用和命名层级通过事务迁移；用户自己建立的符号和引用保留。

导入的 IL 目前只有范围、类别和显示文本，作为分析证据保留，不作为替代 P-code 执行。
语义 lifting 需要结构化操作数、位宽和副作用描述，并与实际指令核对。

## 兼容性

L1 的目标范围是 ARM64 Dart 2.10 至当前稳定版（3.13.7）。
SDK 源码检查覆盖 30 个发布标签；真实二进制验证覆盖部分版本，
尚未逐一验证所有版本和 OS 组合。2.10 之前的版本暂不纳入支持范围。

通用模型根据机器码证据处理栈参数与寄存器参数、新旧写屏障掩码、
单个与成对 Q 寄存器保存，以及新旧 Mint 分配路径。
对于 2.13 时代独立使用 x23 堆基址的 ABI，需要显式选择 `dart-r23`；
该配置从通用编译器规范生成，不依赖快照 hash。

本次修正了无条件 `b.al` 的解码。打开已有数据库时接受 Ghidra 的语言升级，
然后按需重新执行函数发现和 ABI 分析。用户修改过的函数仍受保护。

## 文件与校验

源码按职责组织在 `src/main/java/ghidart/` 下：

- `analysis/`：函数发现、ABI、值／对象使用分析及 P-code 注入。
- `snapshot/`：L2 格式配置、解码、对象、类型与数据库发布。
- `importer/`：ELF 装载、b4a 校验与语义导入。
- `datatype/`：显式长度的字符数据类型。
- `listing/`：原生 Console 动作及兼容已保存布局的操作数字段。

共享日志位于 `analysis/`；迁移的字符和操作数字段类通过 Ghidra 原生类名映射兼容已有数据库和布局。

语言定义位于 `data/languages/`。
构建通过 Ghidra 模块宏引用已安装的官方 ARM64 源码。小型 SLEIGH 包装仅规范化等价的
有符号字运算，保留指令编码和寄存器存储，无需维护另一份指令集。
b4a 数据格式见 [B4A_INTERFACE.md](B4A_INTERFACE.md)。

样例和验证工具仅保留在本地，不进入 Git 或扩展包。本地存在 `tests/VerifyB4a.java` 时，
可运行 `./gradlew --no-daemon verifySamples -PsamplesDir=/path/to/samples` 校验
二进制与 JSON 身份；这不代表已执行 Ghidra 分析。许可与模板来源见 [LICENSE](LICENSE)。

文档默认使用英文。修改本 README 或 [README.md](README.md) 时，必须同步更新另一版本。
接口、样例和测试说明仅维护英文。
